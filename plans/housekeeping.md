房床清单见 [`rooms-and-beds.md`](rooms-and-beds.md)。员工端功能写在工作台仓库 `~/stayCube`；保洁端为小程序分包 `cleaning/`，首页不放入口，扫码进入。界面仅中文。

## 1. 已确认

| 项 | 内容 |
|---|---|
| 绑定 | 员工在工作台生成绑定码，保洁员扫码并点微信登录完成绑定；员工可停用、换绑 |
| 任务来源 | 员工在工作台审核退房、登记布草更换、完成完整换房床、登记平移布草时自动生成 |
| 优先整理 | 完全由员工决定；系统不按入住情况自动排序或标记 |
| 验收 | 保洁员提交后由员工验收；打回不计工作量 |
| 验收联动 | 布草任务验收通过后，自动把工作台的布草登记标为已完成 |
| 补充用品 | 毛巾、minibar、抽纸：旅客没有提出要求时，保洁员不主动更换 |
| 计薪 | 退房整理、布草更换、平移布草各算 1 个床位（完整换房床在保洁端即退房整理），曲江（大床房）算 2 个 |
| 清单 | 员工在后台编辑；初始内容见第 3 节 |
| 借用物品 | 旅客借用的保洁相关物品（被子、枕头等）要告知保洁员：退房整理清单单独列「借用物品」一组，需一并回收；验收通过后工作台借用记录自动标为已归还。哪些物品名称算保洁相关，由员工在后台维护 |
| 回收项 | 「回收」组不是必做项，不勾也能完成；没勾的项在员工验收和记录里显示为「未回收：xxx」，由员工判断是否与实际相符（如旅客未配入住包）。未勾的毛巾、浴巾、地巾不计入送洗数量 |
| 照片 | 保留 60 天后自动删除 |
| 人员 | 目前一名保洁员，按多人设计 |

## 2. 方案要点

### 2.1 任务触发（数据库触发器，监听 `guest_stays.data`）

| 工作台操作 | 数据变化 | 任务 |
|---|---|---|
| 审核退房 | `status` → `checked_out` | 退房整理 |
| 登记布草更换 | `linenRequest.status` → `pending` | 布草更换，日期取 `linenRequest.scheduledOn` |
| 完成完整换房床 | `moveTask.status` → `completed`，`kind = full` | 原床位的退房整理（见 2.1.1） |
| 登记平移布草 | `moveTask.status` → `pending`，`kind = transfer` | 平移布草（见 2.1.1）；验收通过后自动标为完成换房床 |

#### 2.1.1 底层模型：保洁端只有布草的三种操作（讨论中）

退房、换布草、完整换房床、平移布草都是管理端的说法。保洁端只认床位和布草件，系统把管理端事件换算成每张床、每件布草要做什么。

**布草件**：床笠、被套、枕套（曲江：大床笠、大被罩、枕套 ×4、地巾）。每件单独处理，可以只动其中一件。

**三种操作**

| 操作 | 含义 | 送洗 |
|---|---|---|
| 撤脏布草 | 撤下的这件不再使用 | 计入 |
| 铺新布草 | 铺干净的新布草 | — |
| 平移旧布草 | 把另一张床上的这件搬过来铺上 | 不计 |

**两条约束**

1. 撤什么就铺什么：某张床撤下一件，必须铺上同一件。
2. 铺上的只有两种来源：干净的新布草，或从另一张床平移来的。被平移走的那件，在原床位上也算撤下，所以原床位也要铺。

于是每张床、每件布草只有三种结果：**不动**、**换新**（旧的送洗）、**用某床的**（旧的若没有被别的床用走，就送洗）。

**另外两类清单，与布草分开**

| 清单 | 什么时候出现 | 内容 |
|---|---|---|
| 回收 | 有旅客离开这张床（退房） | 入住手袋、毛巾、水杯、借用物品等，按房型；不勾也能完成 |
| 配套确认 | 这张床最后变成空床、等下一位旅客 | 六人间储物柜衣架 ×3、耳塞 ×1；灞上、曲江的房间用品；四人间无 |

**管理端事件的换算**

| 管理端 | 布草 | 回收 | 配套确认 |
|---|---|---|---|
| 退房 B | B 全部换新 | B | B |
| 换布草 B（员工登记时可只选部分件，默认全选） | B 所选件换新 | — | — |
| 完整换房床 A → C，C 已整理好 | A 全部换新；C 不动 | — | A |
| 完整换房床 A → C，C 刚退房 | A 全部换新；C 全部换新 | C 的离店旅客 | A（C 马上入住，不确认） |
| 平移 A → C，C 已整理好 | C 用 A 的，A 用 C 的（干净） | — | A |
| 平移 A → C，C 刚退房 | C 的旧布草撤脏，C 用 A 的，A 换新 | C 的离店旅客 | A |
| 连环平移 A → B → C | C 用 B 的，B 用 A 的，A 换新或用 C 的干净布草 | C 若刚退房 | A |

**保洁端显示**：同一批相互关联的床位合成一条任务，按「先腾出、后铺入」的顺序列出床位（连环平移从最后一张床往前）。每张床下面列出要动的布草件，右边写来源：「换新」或「用 雁塔 A 的」。没有动的件不显示。

**列表归类**（保洁端分「退房」「更换」「平移」三张卡片，每件事只出现在一张卡片里）：

| 管理端 | 卡片 |
|---|---|
| 完整换房床 A → C | 退房：A（C 若刚退房，本来就在退房里） |
| 平移 A → C，C 已整理好 | 平移：A → C |
| 平移 A → C，C 刚退房且退房整理未开始 | 平移：A → C；C 的退房整理并入，从退房卡片消失 |
| 平移 A → C，C 的退房整理已开始 | 退房：C 继续；平移：A → C，详情页提示「先完成 秦都 C 退房」，C 提交前不能开始 |
| 连环平移 | 平移：A → B → C |

**送洗统计**：撤下且没有被别的床用走的布草件。

**工作量**：按管理端事件计——退房、换布草、平移各 1（曲江 2），完整换房床按原床位的退房计，连环平移按平移次数计。只换部分布草时按件累计（每件单独计，曲江也一样，枕套 ×4 算 4 件）：每累计 3 件计 1，不足 3 件的余数带到下个月；整套更换仍计 1。

撤销时自动取消任务：同日再入住会撤回退房，布草或换床被取消时，对应任务也取消。同一床位已有未完成的整理任务时不重复生成。

### 2.2 状态

待整理 → 整理中（保洁员点「开始」） → 待验收（点「完成」） → 已通过；也可能被打回，回到整理中并附打回原因。

### 2.3 多人分配

- 任务可以不指派，所有保洁员都能看到；员工也可以指派给某人。
- 保洁员点「开始」后任务归自己，其他人只能看不能操作；员工可以改派。
- 只有一名保洁员时不需要任何分配操作。

### 2.4 清单与拍照

- 清单模板按「房型 × 任务类型」配置，每项可以设为必做；拍照点单独配置。
- 任务生成时复制当时的模板，之后改模板不影响已生成的任务。
- 必做项全部勾选、拍照点全部拍齐，才能点「完成」。照片压缩后上传。

### 2.5 工作量

- 只统计已通过的任务，按第 1 节计薪规则折算床位数。
- 保洁员看自己的今日、本月；员工端看全部人员，可按日期区间导出。

### 2.6 员工端（工作台）

任务看板（设优先、指派、验收或打回、看照片）、清单模板编辑、保洁员管理（绑定码、停用）、工作量统计。

## 4. 布草送洗统计

用于与洗涤公司对账，只在员工工作台查看和导出，保洁端不显示。

| 项 | 规则 |
|---|---|
| 统计日期 | 按保洁员首次提交的日期；与是否打回无关 |
| 数量修改 | 只有员工可改（验收时或之后）；打回返工另用了布草，由员工补记到该任务 |
| 计入品类 | 床笠、被套、枕套、大床笠、大被罩、毛巾、浴巾、地巾，分别计数 |

每条任务撤下的布草（默认值）：

| 任务 | 合住四人间 | 合住六人间 | 灞上 | 曲江 |
|---|---|---|---|---|
| 退房整理 | 床笠 1、被套 1、枕套 1、毛巾 1 | 床笠 1、被套 1、枕套 1 | 床笠 1、被套 1、枕套 1、毛巾 1 | 大床笠 1、大被罩 1、枕套 4、毛巾 2、浴巾 2、地巾 1 |
| 换布草 | 床笠 1、被套 1、枕套 1 | 同左 | 同左 | 大床笠 1、大被罩 1、枕套 4、地巾 1 |
| 平移布草 | 新床位已整理好：0；新床位刚退房：新床位一套（计在并入的退房整理里） | 同左 | — | — |

完整换房床生成的是原床位的退房整理，按退房整理计。

- 借用物品拆为芯和套：被子 = 被芯（归还入库，不计）+ 被套 1；枕头 = 枕芯（归还入库，不计）+ 枕套 1。退房整理时套子计入撤下布草。
- 退房回收的毛巾、浴巾、地巾即清单「回收」组里的数量，不重复计。
